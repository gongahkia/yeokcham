01

start a local repository

Open the directory you want Yeokcham to manage, then initialize it. The normal command form is deliberately as direct as Git's.

yeokcham init
yeokcham status

02

the workflow

Yeokcham does not have one universal commit. It keeps recovery, chosen intent, and released output as distinct values.

working directoryordinary files
↓
scratchexact checkpoint
↓
intentcapsule revision
↓
workspaceordered attempt
↓
releasevalidated snapshot

Ambiguity, dependencies, and conflicts remain visible instead of being silently resolved.

03

checkpoint & restore

A checkpoint is a local safety record. Inspect it before changing the working directory, and start a restore with a dry run.

yeokcham checkpoint
yeokcham timeline --limit 12
yeokcham restore --dry-run <checkpoint-id>
yeokcham restore <checkpoint-id>

yeokcham pin <checkpoint-id>keep a recovery state

yeokcham compact --dry-run --explaininspect retention before cleanup

04

make intent explicit

A capsule names a logical unit of work. Its caller-supplied ID is stable; each revision is immutable. Yeokcham never infers a capsule from a Git commit.

yeokcham capsule create --current \
  --id search-filter \
  --title "Add search filter" \
  --description "Filter results locally"
yeokcham capsule list
yeokcham capsule show search-filter
yeokcham capsule history search-filter

05

compose a workspace

A workspace declares its base and ordered capsule revisions. If they conflict, the conflict is stored and inspectable; Yeokcham does not invent a text merge.

yeokcham work create --id product-search --base <snapshot-id>
yeokcham work enable product-search <search-filter-revision-id>
yeokcham work explain-order product-search
yeokcham work materialise product-search --dry-run

Inspect an unresolved case with yeokcham conflict list product-search.

06

validate & release

Validation runs against a named immutable snapshot in a fresh temporary directory. A release records the verified workspace composition and final snapshot.

yeokcham validation run \
  --snapshot <snapshot-id> \
  --exec make --arg check
yeokcham release create \
  --workspace product-search \
  --message "Search filters"
yeokcham release verify <release-id>

A native release records reproducibility. External source-release signing and distribution are separate procedures.

07

share deliberately

Git preservation and peer publication are explicit interchange boundaries. The receiving repository chooses whether to make a new local capsule.

yeokcham git import commit \
  --repository /absolute/git-dir \
  --commit <full-git-commit-id>
yeokcham peer publish capsule \
  --capsule search-filter \
  --revision <revision-id>

yeokcham peer fetch \
  --from /absolute/source-root \
  --publication <publication-id>

08

inspect what you have

These commands read and explain the repository. They do not repair or silently mutate it.

yeokcham status
yeokcham timeline --limit 32
yeokcham history --graph
yeokcham storage stats
yeokcham verify
