The short version

A calm workflow for work that is still becoming clear.

Checkpoints make experimentation recoverable. Capsules name the work you want to keep. Workspaces assemble selected capsule revisions. Releases preserve the exact result after validation. Each layer answers a different question.

01 — setup

Start with a directory, not a commit.

Yeokcham manages a local working directory. The setup commands use the checked-out executable through Dune; subsequent examples use yeokcham for readability after installation.

a

Prepare the checkout

Install dependencies and confirm the executable is available.

make setup
make check
dune exec bin/yeokcham.exe -- --help
b

Initialize a working directory

Run from the Yeokcham checkout and point the command at the directory you want to manage.

dune exec bin/yeokcham.exe -- init \
  --root /path/to/project
dune exec bin/yeokcham.exe -- status \
  --root /path/to/project

02 — recovery

Checkpoint often. Restore deliberately.

A checkpoint is a local safety record, not a collaboration claim. Use the timeline to inspect it before changing the working directory.

•••recovery loop

$ yeokcham checkpoint

checkpoint=ckpt_… changed-paths=src/app.ml

$ yeokcham timeline --limit 12

retained checkpoint · current safety state

$ yeokcham restore --dry-run <checkpoint-id>

plan=ready · working tree unchanged

$ yeokcham restore <checkpoint-id>

Safety boundary

Start with --dry-run. Restore protects divergent work with a safety checkpoint and verifies the intended result before moving the scratch head.

yeokcham pin <checkpoint-id>keep a specific recovery state
yeokcham compact --dry-run --explaininspect retention before cleanup
yeokcham history --graphinspect typed native history

03 — intent

Turn selected work into a capsule.

A capsule names one logical unit of work. Its caller-supplied ID stays stable while each revision is immutable, so changing an implementation does not rewrite its meaning.

01

Create from current work

yeokcham capsule create --current \
  --id search-filter \
  --title "Add search filter" \
  --description "Filter results locally"
02

Inspect before revising

yeokcham capsule list
yeokcham capsule show search-filter
yeokcham capsule history search-filter
03

Keep uncertainty explicit

Dependencies, ordering, and conflicts are declared values. A capsule is never silently inferred from a Git commit or a peer publication.

04 — composition

Build a workspace from chosen revisions.

A workspace has a declared base and ordered capsule revisions. Yeokcham explains the order and stores conflicts as inspectable values instead of inventing a text merge.

base snapshot→capsule revisions→workspace attempt
yeokcham work create --id product-search --base <snapshot-id>
yeokcham work enable product-search <search-filter-revision-id>
yeokcham work explain-order product-search
yeokcham work materialise product-search --dry-run

Conflict? Inspect it with yeokcham conflict list product-search. Unrelated work remains available.

05 — validation and release

Release one exact, reproducible result.

Validation runs against a named immutable snapshot in a fresh temporary directory. A release records the verified workspace composition and final snapshot; it is not a renamed checkpoint or capsule.

01

Validate a snapshot

yeokcham validation run \
  --snapshot <snapshot-id> \
  --exec make --arg check
02

Create the release

yeokcham release create \
  --workspace product-search \
  --message "Search filters"
03

Verify it later

yeokcham release list
yeokcham release show <release-id>
yeokcham release verify <release-id>

A native release records reproducibility. External source-release signing and distribution are separate, explicit procedures.

06 — interchange and sharing

Keep foreign history foreign. Share deliberately.

Git preservation is an explicit migration boundary. Peer publication transfers a verified projection; the receiving repository chooses whether to create a new local capsule. Neither operation makes a workspace selection for you.

↔

Git interchange

Preserve and adopt without pretending equivalence.

yeokcham git import commit \
  --repository /absolute/git-dir \
  --commit <full-git-commit-id>
⇄

Peer publication

Receive a proposal, then explicitly integrate it.

yeokcham peer publish capsule \
  --capsule search-filter \
  --revision <revision-id>

yeokcham peer fetch \
  --from /absolute/source-root \
  --publication <publication-id>

07 — inspect

When in doubt, inspect the state you have.

These commands read and explain the repository. They do not repair or silently mutate it.

yeokcham statuscurrent local state
yeokcham timeline --limit 32retained scratch checkpoints
yeokcham history --graphtyped native history, not one commit graph
yeokcham storage statsstorage by history domain
yeokcham verifyhashes, reachability, and reproducibility
