# Research questions

These are open questions, not product claims.

1. What checkpoint-retention policy gives useful recovery coverage at bounded
   storage and restore cost? Measure before changing retention semantics.
2. How does the Linux watcher behave under real inotify limits, rapid rename
   storms, overflow, and restart? The dedicated Linux loop remains to be run.
3. What review interface makes authority forks and late-adoption consequences
   comprehensible without hiding branch scope or treating review as intent?
4. How should a future transport carry already-verified package closures while
   preserving the same no-partial-import boundary?
5. What device-custody interface can support non-exportable keys without
   letting a custody provider become identity or authority?
6. Under what proof and recovery constraints can blob reclamation be added
   without losing snapshots, decisions, packages, or restore safety?
7. Which Git interchange, if any, can retain foreign provenance without
   translating Git topology into Yeokcham intent?
